====================================================================
 유저 캐릭터 & 파트너 드래곤 전투 시스템 정리 (기능 및 구조 기준)
====================================================================

1. 구조 (Structure)
--------------------------------------------------------------------

[관련 클래스 맵]

PlayerController (Rigidbody 이동형)          DragonController (Transform 이동형)
  - Animator (BasicCharacterStance)            - Animator (BasicDragonStance)
  - CombatStatComponent  ---+                  (CombatStatComponent 없음
  - HealthComponent          |                  -> 공격력 항상 0으로 계산됨)
  - PlayerCharacterModel     |                 - HealthComponent(있으나 실제
                             |                   피격 대상으로 쓰이진 않음)
                             |                 - DragonProjectile(Q 스킬 전용
                             |                   투사체)
                             v
        +-----------------------------------------+
        |   공용 전투 파이프라인 (양쪽이 재사용)     |
        |   CombatCalculator (데미지 공식)          |
        |   CombatStatComponent (공격력/방어력)     |
        |   HealthComponent (체력, IDamageable)     |
        |   DamageInfo (원본데미지 + 공격자)        |
        +-----------------------------------------+
                             |
                             v
                 MonsterController / MonsterModel
                 (실질적으로 유일한 피격 대상)

[데이터 소스]
- PlayerController -> SkillDataModelSO (A/S/D/F 스킬명 / 쿨타임 / 데미지)
- DragonController -> DragonSkillDataModelSO (Q/W/E/R 스킬명 / 쿨타임 / 데미지)
- 둘 다 GameSceneController가 Addressable로 로드해 각 컨트롤러에 주입하고,
  KeyboardInputController의 입력 이벤트(공격 / A·S·D·F / Q·W·E·R)를 구독해
  UI_GameSceneView.TryStartXXXCooldown()이 성공했을 때만 실제 스킬 메서드를
  호출한다.

[애니메이터 레이어 공유 구조]
- Player/Dragon 모두 Base Layer(이동/대기) + Attack Layer(공격/스킬/피격)
  2개 레이어를 사용한다.
- Attack Layer는 평소 weight=0으로 꺼져 있다가, 콤보·스킬·피격 중 어느
  하나라도 재생될 때만 weight=1로 켜진다.
- 셋이 같은 레이어를 공유하므로 서로의 타이머를 취소해가며 덮어쓰지 않게
  관리한다(예: 공격 도중 피격당하면 공격 종료 타이머를 취소하고 즉시 피격
  연출로 전환).


2. 기능 (Function)
--------------------------------------------------------------------

[2-1. 플레이어 공격 기능]

  기능              | 트리거        | 내용
  ------------------|---------------|--------------------------------
  기본 콤보         | 공격 키       | 2단 콤보(Combo01/02), 콤보 유예시간
                    |               | 내 재입력 시 다음 단으로 이어짐,
                    |               | ComboIndex 파라미터로 애니메이션 제어
  스킬 A(찌르기)    | A키, CD 3s    | 단일 히트, OverlapSphere로 즉시 판정
  스킬 S(삼단베기)  | S키, CD 5s    | 3연타 클립을 순차 재생하며 타격마다
                    |               | 개별로 데미지 판정(1회 데미지값이
                    |               | 3번 곱해지는 구조라 이번 세션에
                    |               | 수치를 재조정함)
  스킬 D(속성부여)  | D키, CD 10s   | 직접 데미지 없는 버프 스킬: 8초간
                    |               | 콤보 이펙트가 화염형으로 바뀌고,
                    |               | CombatStatComponent.SetBonusAttackPower
                    |               | 로 공격력이 소폭(+3) 상승
  스킬 F(회전베기)  | F키, CD 8s    | 단일 히트 + 회전 이펙트

- 모든 판정은 PlayerController.TryDealDamage() 한 곳으로 통일: 캐릭터
  기준 로컬 오프셋에서 Physics.OverlapSphereNonAlloc으로 범위 내
  IDamageable을 찾아 데미지 적용
- 데미지 = CombatCalculator.CalculateAttackDamage(CombatStatComponent.
  AttackPower, skillDamage)

[2-2. 드래곤 스킬 기능]

  슬롯               | 방식                                | 대상판정 | 상태
  -------------------|--------------------------------------|----------|------------------
  Q(파이어볼)        | 투사체(DragonProjectile)가 실제로     | O        | 정상 동작
                     | 날아가며 매 프레임 이동+명중판정        |          |
  R(메테오 스트라이크)| 투사체 없이 목표 지점에 즉시 범위 데미지| O        | 정상 동작
  W(드래곤 포스)     | -                                     | -        | 데이터만 있고
                     |                                        |          | 실제 발동 코드
                     |                                        |          | 없음(미구현)
  E(드래곤 피어)     | -                                     | -        | 데이터만 있고
                     |                                        |          | 실제 발동 코드
                     |                                        |          | 없음(미구현)

- 드래곤은 CombatStatComponent가 없어 공격력이 항상 0 -> 스킬 데미지 값이
  곧 최종 원본 데미지(성장/레벨 반영 안 됨)
- 플레이어 오인사격 방지: Q/R 모두 hitCollider.GetComponentInParent
  <MonsterModel>() == null 이면 무시하는 화이트리스트 방식으로, 몬스터
  외(특히 플레이어)에게는 절대 데미지가 들어가지 않도록 예외처리되어
  있음(이전 세션에서 명시적으로 추가한 로직)

[2-3. 공용 데미지 파이프라인]

  공격측: rawDamage   = max(0, 공격력) + max(0, 스킬데미지)
  피격측: finalDamage = max(1, rawDamage - max(0, 방어력))   // 최소 1 보장

- HealthComponent.TakeDamage(DamageInfo)가 유일한 진입점 - Player/Monster
  공용
- 체력 변화 시 OnHealthChanged(UI 갱신용), OnDamaged(피격 연출 트리거용),
  OnDied(사망 처리용) 3개 이벤트로 분리되어 있어 각 구독자가 필요한 것만
  반응한다.

[2-4. 피격 리액션 & 행동 잠금] (Player만 해당 서술, Monster도 동일 패턴)

- HealthComponent.OnDamaged 구독 -> PlayHitReaction()
  - GetHit01/02 중 랜덤 재생(HitIndex 파라미터, Attack Layer의 AnyState 전환)
  - HitNormal 이펙트를 캐릭터 위치에 소환
  - isHitReacting 플래그로 이동/점프/콤보/스킬을 전부 잠그고, 지속시간 후
    자동 해제
  - 진행 중이던 콤보/스킬이 있었다면 즉시 중단(comboStep=0, isSkillPlaying
    =false)하고 피격 연출을 우선한다.

[2-5. UI 연동]

- UI_GameSceneView: A/S/D/F, Q/W/E/R 각 슬롯의 쿨타임을
  TryStartPlayerSkillCooldown / TryStartDragonSkillCooldown으로 관리
  (색상 트윈 + 카운트다운 텍스트)
- 몬스터를 감지(OnTargetDetected)하면 몬스터 정보 패널(이름/등급/HP바/
  HP텍스트)이 자동으로 뜨고 매프레임 갱신되어, 전투 중 실시간으로 상대
  체력을 확인할 수 있다.


3. 구조적 특징 요약
--------------------------------------------------------------------
- 재사용성: 공격력/방어력/체력/데미지 계산이 전부 공용 컴포넌트라, 새
  캐릭터(예: 다른 종류의 몬스터·NPC)를 추가해도 HealthComponent +
  CombatStatComponent만 붙이면 동일한 전투 파이프라인에 바로 편입된다.
- 레이어 공유로 인한 상호배제 설계: 콤보/스킬/피격이 하나의 Attack Layer를
  공유하므로, 상태 전환 시 서로의 Invoke 타이머를 취소하는 방어적 코드가
  곳곳에 있다(연출이 씹히지 않도록).
- 비대칭 구조: Player는 근접(OverlapSphere 즉시판정) 중심, Dragon은
  원거리(투사체/AoE) 중심으로 역할이 명확히 분리되어 있다.
- 미완성 지점: Dragon W/E, 그리고 Dragon 자체 성장(dragonLevel/
  DragonStats)이 전투 수치에 전혀 반영되지 않는 점이 구조적 공백으로
  남아있다.
